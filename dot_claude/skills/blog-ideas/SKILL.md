# Blog Ideas スキル

インプットは溜まっているのに記事にならない原因の一つは「どれを書くか決める場がない」こと。このスキルは素材を読んで候補を絞り、選ぶだけの状態にする。

## 設定

- **Vaultパス**: `/Users/hakshu/Library/Mobile Documents/iCloud~md~obsidian/Documents`
- **ネタ帳**: `{VAULT}/ブログ/ネタ帳.md`
- **下書きフォルダ**: `{VAULT}/ブログ/drafts/`
- **ブログリポジトリ**: `~/workspace/hakshu.blog`（公開済み記事は `content/articles/*.md`）

---

## 実行フロー

### ステップ1: 素材を集める

直近7日間に更新されたノートを対象にする。

```bash
VAULT="/Users/hakshu/Library/Mobile Documents/iCloud~md~obsidian/Documents"
find "$VAULT" -name "*.md" -mtime -7 \
  -not -path "*/.obsidian/*" -not -path "*/ブログ/*" -not -path "*/Templates/*"
```

- `調査ログ/` は最優先で読む。1本がそのまま1記事になりやすい。
- `日報/` は「メモ」「振り返り」セクションを読み、ハマったこと・気づき・繰り返し出てくる話題を拾う。
- `Readwise/`・`kindle/` はハイライトそのものではなく、日報や調査ログの話題と重なるものを補強材料として拾う。
- 直近7日の素材が乏しい（2件以下）ときは、`調査ログ/` とVault直下のノート全体から、まだ記事になっていないものを拾う。

### ステップ2: 既出を除く

次のものと重なる候補は出さない。

- `ネタ帳.md` に既にある候補（チェック済み・未チェックとも）
- `ブログ/drafts/` にある下書き
- `~/workspace/hakshu.blog/content/articles/` の公開済み記事

### ステップ3: 候補を絞る

最大3つ。数を揃えるために弱い候補を足さない。良いものがなければ1つでも0でもいい。

選ぶ基準：

- **1記事1発見**に収まる。大作になりそうなら分割して最初の1本だけ候補にする。
- 本人の経験・判断・ハマりどころが含まれている。公式ドキュメントの要約にしかならないものは外す。
- 元ノートだけで骨子の7割が埋まる。追加調査が大量に要るものは外す。

いちばん書きやすいものに「おすすめ」を付ける。

### ステップ4: ネタ帳に追記する

`ネタ帳.md` がなければ作る。既存の内容は消さず、先頭の見出しの直下に今回分を追記する（新しい週が上）。

```markdown
# ブログ ネタ帳

## 2026-09-21 週

- [ ] **Vite+ に移行してビルド構成がどう変わったか**（おすすめ）
  - タイプ: 移行記 ／ 規模: 中
  - 想定読者: Vite+ を試そうか迷っている人
  - 言いたいこと: 設定ファイルが1つにまとまる代わりに、override の仕組みを理解していないとハマる
  - 元ノート: [[vite-plus ビルド構成調査]] [[vite-plus pnpm build スクリプト調査]]
  - 足りないもの: 移行にかかった時間、移行前後のビルド時間
```

- タイプは `技術Tips`／`移行記`／`調査まとめ`／`イベントレポート`／`振り返り` のいずれか。
- 規模は `小`（2,000字前後）か `中`（4,000字前後）。
- 「足りないもの」は、インタビューで本人に聞く必要があることを書く。`blog-draft` がここを質問に使う。

### ステップ5: 報告

対話実行のときは候補を一覧で見せ、「どれか選んだら `blog-draft` で骨子を作るよ」と伝える。

スケジュール実行のときは質問せず、追記した候補のタイトルだけを短く報告して終わる。

---

## エラーハンドリング

- **`ブログ/` フォルダがない**: 作成してから進む。
- **Vaultにアクセスできない**（iCloud未同期など）: 何も書かずにその旨を報告して終わる。
- **仕掛かり中の下書きがある**: 候補は出すが、報告の最初に「先に仕掛かり中の『〜』を終わらせるのがおすすめ」と添える。
